# 最近邻工作缺口与下一轮定向检索规范

## 1. 已完成覆盖

当前已核验 16 篇机制最近邻，覆盖：

- 从用户交互发现运行时需求；
- 生产监控对象/指标推荐；
- 告警价值、反馈驱动阈值和告警抑制；
- 无标签异常检测器选择；
- 已有 SLO 的扩散与预测监控；
- 测量充分性停止规则；
- 微服务故障前预测和拓扑诊断；
- 时间序列异常检测评价协议。

这些工作已经足以否定“本文首次使用运行数据、人工反馈、拒绝或预测”的表述。

## 2. 尚未完全覆盖的高风险问题

| 缺口 | 精确检索问题 | 为什么重要 | 允许新增量 |
| --- | --- | --- | --- |
| 2025—2026 数据驱动 SLO mining | 是否有方法在无正式 SLO 时，从遥测生成服务级数值目标，并输出置信度/拒绝？ | 可能直接削弱核心创新 | 2—4 篇高相关 |
| Quantitative requirements at runtime | 是否有运行时需求方法在目标缺失或不确定时生成候选区间并升级人工？ | 当前只比较了一篇交互发现工作 | 2—3 篇 |
| Selective prediction / defer / abstain in SE/AIOps | 是否把证据不足作为可审计拒绝状态，并保留批准权？ | 决定“拒绝治理”是否新 | 2—3 篇 |
| 动态告警阈值的证据质量 | 是否同时处理覆盖、分辨率和尾部上下文，而不是只优化检测分数？ | 决定四状态是否只是常见质量门禁 | 2—3 篇 |
| 2024—2026 微服务预测/诊断 | RCAEval、SAGE、TVDiag 等工作如何定义任务、外部协议和拓扑输入？ | 只用于限制预测/拓扑主张，不建立新贡献 | 2—4 篇 |

## 3. 检索与纳入标准

只纳入能够回答至少一个机制问题的论文：

1. 是否要求已有 SLO；
2. 是否生成候选数值；
3. 是否显式审计证据质量；
4. 证据不足时能否拒绝或转交；
5. 是否保留利益相关者批准权；
6. 是否有独立或外部验证。

每篇必须记录：正式题名、作者、年份、出版物、DOI/稳定链接、任务输入、输出、拒绝行为、人工角色、验证设计、与本文的重叠和决定性差异。

## 4. 停止条件

- 高风险类别连续两组检索不再出现新的机制组合；
- 已找到最可能同构的方法，或确认它需要本文没有的已有 SLO/反馈/标签；
- 新文献只会增加一般背景，不改变表 1 的六维结论；
- 预计新增正文引用不超过 3—8 条，参考文献总量不是目标。

下一轮检索前不再重做图片或扩实验；检索结果只决定原创性措辞和表 1，不用于追逐正结果。
