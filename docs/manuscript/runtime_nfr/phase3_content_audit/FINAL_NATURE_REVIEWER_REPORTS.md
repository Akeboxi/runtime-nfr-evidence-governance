# Runtime NFR 三视角压力测试（内容关闭版）

## Reviewer 1：编辑与专刊契合度

总体判断：稿件目前具有可辨识的需求工程问题和稳定主线。贡献不是“更好的阈值”，而是把描述性遥测与规范性目标之间的责任断点实现为可审计协议；“拒绝操作化”作为正常输出，与智能化需求工程、运行时需求、质量评估和不确定性治理直接相关。

主要优点：

- 摘要、引言和结论均维持三项贡献，预测和拓扑不再作为并列创新。
- 2025—2026 最近邻工作已进入六维对比，原创性不依赖“首次”表述。
- 负结果、外部拒绝和利益相关者批准权被保留，避免自动化越权。

主要风险：

- 单一内部环境且缺少正式 SLO 终点，无法支持广泛外部有效性。
- 相关工作表是定位工具，不是系统综述；投稿时不应把检索范围写成完备性声明。
- 2026-07-30 已确认中英文作者顺序、单位、通信作者、基金、利益冲突及
  代码可公开边界；代码当前私有保存、论文接收后公开，公开仓库地址、
  许可证、持久标识符及投稿声明最终字段仍属于流程待办，而非科学内容问题。

建议姿态：达到“可送外审但主张范围必须保持克制”的内容状态。

## Reviewer 2：方法与反方视角

总体判断：最强反对意见仍是“作者定义规则后再证明规则会改变输出”。当前稿件通过三层限制回应：threshold-only 只承担信息暴露角色；规则删除报告迁移目的地而非优劣；专家评价拆分阈值与治理对象。它不能证明 0.5/720/10.0 最优，但已不再提出这一主张。

主要优点：

- 候选公式、治理顺序、时间协议、禁止特征和硬失败条件均可由代码—正文审计。
- origin→counterfactual 迁移给出了删除历史门禁后 311/134/609 的具体去向，而非只报改变总数。
- 9.5/10.0/10.5 仅作冻结政策敏感性，不用于阈值选择。
- 41 项测试、正式结果哈希和历史完整性审计均通过。

主要风险：

- 专家看到证据状态和建议动作，高治理评分可能反映对保守决策的偏好。
- threshold-only 没有客观阈值正确性或业务终点，不能写成性能基线。
- 图 1 的原始遥测是可访问历史窗末端片段，不足以独立重建完整 24 h 门禁。

建议姿态：方法定义和证据角色已可审计；保留上述限制后，不需要追加实验。

## Reviewer 3：需求工程与非专业读者视角

总体判断：文章最清晰的命题是“数据能够描述过去，但无权自动规定未来目标”。候选、证据、动作和批准权四层结构对 Runtime Requirements 与 NFR operationalization 读者可解释，且图 1—2 已把该结构变成视觉论证。

主要优点：

- 责任对象被拆分：算法生成候选、证据门禁决定是否拒绝或补证、专家评价治理、利益相关者保留目标批准权。
- RQ4 使用实现、外部协议、下游使用和表示扩展四类边界，避免把异质证据合并成“验证成功”。
- 专家反例、服务异质性、校准偏差和静态拓扑限制均进入正文。

主要风险：

- 结果部分仍然信息密集，读者需依靠 RQ 小结维持主线。
- “证据感知”容易被误读为统计置信度；正文必须继续使用具体字段和责任动作解释。
- 组织内审批、协商与目标变更没有被研究，当前协议只建立到转交和签署的基础链。

建议姿态：适合专刊主题；语言润色应以术语统一和压缩重复边界为主，不应改写科学含义。

## 综合判定

三位审稿视角一致认为，没有剩余 P0 科学内容阻塞项。可接受的核心主张是“证据责任协议＋失败保持治理及其实证”，不可接受的扩张包括阈值正确、规则最优、正式 SLO 自动发现、正向外部有效、独立预测创新和拓扑/GNN 普遍无效。

本轮唯一新增的实质性正文修复是补足专家设计的非盲化边界及其对高治理评分的替代解释。其余问题已由最近邻定位、规则迁移、分层结果、v3 图表和范围降级关闭。
